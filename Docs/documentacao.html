1Visão Geral do Sistema

O sistema implementa um pipeline de Extração, Transformação e Carga (ETL) de imagens de satélite Sentinel-2, processadas na nuvem pelo Google Earth Engine (GEE), com o objetivo de identificar e visualizar a distribuição desigual de vegetação urbana no município do Rio de Janeiro.

O resultado é exibido em um mapa interativo acessível via navegador, com camadas alternáveis de imagem real (RGB), detecção de corpos hídricos (MNDWI) e mapeamento de vegetação urbana (NDVI). As imagens são atualizadas sob demanda por meio de um servidor local em Python (Flask), sem necessidade de recarregar a página.

Escopo atual: A versão documentada contempla o pipeline ETL com GEE, o servidor Flask e a interface Leaflet. Módulos futuros — banco PostGIS, dashboard Streamlit e análise espacial (Gini, Getis-Ord Gi*) — serão documentados em versão subsequente.

3Pipeline ETL

3.1 Descrição das Etapas

Extração: A coleção COPERNICUS/S2_SR_HARMONIZED é filtrada por localização (ponto de interesse no RJ), período (2025) e cobertura de nuvens inferior a 10%. Os valores de reflectância são normalizados pela divisão por 10.000.

Transformação: Calcula-se a mediana temporal da coleção para obter uma imagem sem nuvens. Sobre ela são aplicadas as fórmulas de MNDWI (detecção hídrica) e NDVI (vegetação). O NDVI é mascarado nas áreas identificadas como água e filtrado pelo limiar de 0,25 para eliminar ruídos de telhados e solo exposto.

Carga: Cada imagem transformada é publicada como camada de tiles XYZ autenticada via getMapId(). As URLs são armazenadas em cache no servidor Flask e entregues ao frontend via API REST.

7.2 Google Earth Engine API

☁️

earthengine-api v1.7.x

Google LLC · developers.google.com/earth-engine · Licença Apache 2.0
O que é

SDK Python para a plataforma Google Earth Engine — um serviço de computação geoespacial em nuvem que disponibiliza petabytes de imagens de satélite e dados geoespaciais públicos, incluindo toda a coleção Copernicus Sentinel-2. O processamento ocorre nos servidores do Google, não localmente.

Modelo de execução (lazy evaluation)

As operações Python não executam imediatamente. Cada chamada como ImageCollection.filter() ou normalizedDifference() constrói um grafo de computação (AST) que é enviado ao servidor GEE apenas quando um resultado concreto é solicitado — como em getMapId(). Isso permite compor pipelines complexos sem trafegar dados volumosos.

Uso no projeto

Extração: ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED') acessa a coleção Sentinel-2 com filtros de localização, data e cobertura de nuvens.

Transformação: normalizedDifference() calcula NDVI e MNDWI; updateMask() aplica máscaras; median() compõe imagem livre de nuvens por estatística temporal.

Carga: getMapId() registra a imagem no GEE e retorna uma URL de tiles XYZ autenticada, válida por algumas horas, que o Leaflet consome diretamente.

Características relevantes
Computação em nuvemLazy evaluationGrafo computacionalTiles XYZ autenticadosAcesso gratuito para pesquisa

7.3 Flask

🌶️

Flask v3.1

Pallets Projects · flask.palletsprojects.com · Licença BSD-3-Clause (open source)
O que é

Microframework web para Python. "Micro" significa que o núcleo é mínimo e sem opinião — não impõe ORM, sistema de autenticação ou estrutura de projeto. É extensível via plugins. Amplamente usado para APIs REST, protótipos e aplicações de pequeno a médio porte.

Por que Flask e não FastAPI ou Django

Flask foi escolhido pela simplicidade: o projeto exige apenas 3 rotas GET sem autenticação de usuário, sem banco de dados e sem schemas complexos. FastAPI adicionaria overhead de tipagem e validação desnecessários; Django seria superdimensionado para o escopo atual.

Uso no projeto

GET / — serve o arquivo area_verde.html via send_from_directory().
GET /api/tiles — retorna o cache de URLs (ou status de carregamento).
GET /api/refresh — reexecuta o pipeline GEE e devolve novas URLs.

A função jsonify() do Flask serializa dicionários Python em JSON com os headers HTTP corretos (Content-Type: application/json), permitindo que o JavaScript do frontend consuma a resposta com fetch().json().

Características relevantes
WSGIRoteamento por decoradorServidor de desenvolvimento embutidoExtensível via blueprints

7.4 Leaflet.js

🗺️

Leaflet.js v1.9.4

Vladimir Agafonkin · leafletjs.com · Licença BSD-2-Clause (open source)
O que é

Biblioteca JavaScript de código aberto para mapas interativos no navegador. Com ~42 KB minificados, é a mais popular do gênero. Suporta tiles XYZ, GeoJSON, marcadores, popups, eventos de mapa e é extensível via plugins.

Como funciona o sistema de tiles

O mapa é dividido em uma grade de imagens quadradas de 256×256 px chamadas tiles. Cada tile é identificado por três coordenadas {z}/{x}/{y}, onde z é o nível de zoom e x/y são posições na grade. Ao navegar, o Leaflet calcula quais tiles estão visíveis e faz requisições HTTP paralelas para buscá-los. Quando o GEE recebe a requisição de um tile, executa o pipeline apenas para aquela região, retornando uma imagem PNG renderizada.

Uso no projeto

L.map() — inicializa o mapa no elemento #map, centralizado no RJ com zoom 13.
L.tileLayer(url) — cria uma camada de tiles a partir de uma URL de template. Usado para o mapa base (OSM/Esri/Google) e para as 3 camadas GEE.
layer.setOpacity() — controla transparência em tempo real sem recarregar tiles.
map.removeLayer() / addTo(map) — adiciona e remove camadas dinamicamente.
layer.bringToBack() — garante que o mapa base fique abaixo das camadas GEE na ordem Z.

🛰️

ESA / Copernicus Programme · Acesso público gratuito via GEE
O que é

Coleção de imagens do satélite Sentinel-2, desenvolvido pela Agência Espacial Europeia (ESA) no âmbito do programa Copernicus. O produto SR (Surface Reflectance) já passou por correção atmosférica — os valores representam a reflectância real da superfície, eliminando interferências da atmosfera. Harmonized indica calibração consistente entre as plataformas Sentinel-2A e Sentinel-2B.

7.6 Fetch API (JavaScript nativo)

⚡

Fetch API Web Standard

WHATWG · Nativa nos navegadores modernos · Sem instalação
O que é

API nativa do navegador para realizar requisições HTTP de forma assíncrona, substituindo o antigo XMLHttpRequest. Baseada em Promises e compatível com async/await, permite que o JavaScript espere respostas do servidor sem bloquear a interface do usuário.

Uso no projeto

Implementa duas interações críticas sem recarregar a página:

Polling inicial: loop de até 30 tentativas chamando fetch('/api/tiles') a cada 1,5 s enquanto o GEE processa. Quando o servidor responde com status: ok, as URLs são aplicadas ao Leaflet e o overlay de carregamento é removido.

Botão Atualizar: chama fetch('/api/refresh') e aguarda a resposta (~10–20 s). Ao receber as novas URLs, substitui as camadas Leaflet em memória — sem nenhum recarregamento de página.

Características relevantes
Baseada em Promisesasync/awaitSem dependência externaCORS suportadoStreaming de respostas
